# Operations

## First run

```text
cargo build --release                       # target/release/spool; use an absolute path for services
spool init                                  # config, 0700 dirs, handle-signing key (0600); reads no transcripts
spool service install && spool service start
spool doctor
```

`spool init` reports the recognized source roots and what is enabled. Choose explicitly:

* interactive (TTY): it asks per source (default: no) and whether to allow hosted embedding (default: no);
* non-interactive: `--enable-source ID`, `--disable-source ID` (repeatable), `--hosted-processing
  yes|no`. With no flags it keeps the safe defaults (no source enabled, hosted processing off) and
  says so. An existing `config.toml` is left alone; flags against an existing config are refused
  unless `--force` is given.

Hosted embeddings additionally need the provider key in `secrets/provider.key` (mode 0600, only the
key). Without it Spool is lexical-only; `doctor` and `status` report the two causes (not approved
vs. no credential) distinctly.

## Running the daemon

* Foreground: `spool daemon run` (Ctrl-C / SIGTERM stops it; graceful target 15 s).
* macOS service: `spool service install` writes `~/Library/LaunchAgents/com.spool.daemon.plist`
  (`ProgramArguments = [ABS_BIN, daemon, run]`, `RunAtLoad`, `KeepAlive` on non-zero exit,
  `ThrottleInterval` 30 s, stdout/stderr in `~/Library/Logs/Spool/daemon.*.log`, fixed minimal
  environment) and bootstraps it into `gui/<uid>`; because of `RunAtLoad` the daemon starts at
  install. `start` = bootstrap if needed + `launchctl kickstart`; `stop` = `launchctl bootout`
  (stays stopped until `start` or next login); `restart` = `kickstart -k`; `uninstall` = bootout +
  remove the plist. It is a per-user agent: it runs in your login session, not while logged out
  and not necessarily while the machine sleeps; discovery reconciles after restart/wake.
* Linux: `spool service install` writes `~/.config/systemd/user/spool-daemon.service`
  (`Restart=on-failure`, `TimeoutStopSec=20`) and runs `systemctl --user daemon-reload` and
  `enable`; `spool service start` starts it. Lingering is **not** enabled: the service runs while you
  are logged in. To keep it running after logout, run `loginctl enable-linger $USER` yourself.
* Install never needs root, never overwrites a definition spool did not write (it errors), and
  `uninstall` keeps your configuration, index, keys and credential.
* `packaging/` contains illustrative copies of the rendered definitions. Do not install those by
  hand.

## Backfill and maintenance

```text
spool index --since 30d --dry-run     # candidate counts, local token estimate, exclusions; no provider call
spool index --since 30d --wait        # durable operation; --wait polls and prints progress
spool index --all [--source omp]      # explicit; never triggered by search
spool index --session SESSION_ID
spool jobs status|retry|cancel OPERATION_ID
spool index rebuild [--lexical-only | --embeddings-only]
spool index remove --session ID --exclude
spool index purge --unreferenced      # removes unreferenced derived vectors/text; not forensic erasure
spool sources list | enable ID | disable ID
spool handles rotate-key              # revokes every issued handle and cursor
```

* `--since` accepts `7d`, `12h`, `30m`, `2w`, or a date/time (`2026-10-01`, `2026-10-01T08:30`,
  RFC 3339). Relative values are resolved against the current time and `--tz` (`UTC` by default, or a
  fixed offset such as `+02:00`; named zones are not supported). The resolved absolute cutoff is
  printed before the request is sent.
* Disconnecting a `--wait` (Ctrl-C) never cancels the operation; use `spool jobs cancel` for that.
  Cancellation is cooperative and keeps already committed progress.
* Mutating commands carry an idempotency key generated by the CLI.

## Status, doctor, logs

* `spool status [--json]` asks the daemon for state, queues, workers, coverage and budgets.
* `spool doctor [--json] [--probe-provider]` checks: configuration validity; directory/socket/file
  permissions (0700/0600) including the signing key, credential file, databases and WAL files;
  signing key loadability; databases; SQLite + FTS5 capability (an offline in-memory probe; live
  databases are never opened by `doctor`); each source's roots and adapter registration; embedding
  profile and consent state; daemon/queue/worker health through the daemon's status; service
  registration; log directory. Exit code 1 if any check fails; warnings (e.g. daemon not running,
  service not installed) do not fail. `--probe-provider` is the only check that contacts a provider
  and only when hosted processing is approved and a credential exists.
* `spool logs [--lines N] [--follow]` tails `spool.log` (`~/Library/Logs/Spool` on macOS,
  `<state>/logs` on Linux). Files rotate at `logging.max_file_bytes`, keeping
  `logging.retained_files` older files. Logs never contain conversation or query text.

Exit codes: 0 success; 1 failure or invalid arguments (rejected before any daemon call); 2 command
line usage error (clap); 3 daemon unreachable (the message names the socket and the start commands
`spool service start` / `spool daemon run`).

## Backup and restore

Back up with SQLite's backup facility, **not** by copying the `.sqlite` file: the database runs in
WAL mode, so a plain copy of the main file can miss committed data held in `-wal`, and a copy taken
mid-write can be inconsistent.

```text
sqlite3 "$SPOOL_HOME/state/index.sqlite" ".backup '/path/to/index-backup.sqlite'"
chmod 600 /path/to/index-backup.sqlite
```

`.backup` uses the online backup API and is safe while the daemon runs (the default home is
`~/Library/Application Support/Spool` on macOS). Alternatively stop the service first
(`spool service stop`) and take the backup offline. `jobs.sqlite` holds only Apalis execution state
and can be skipped (a restored index re-discovers sources). The backup contains conversation text
and vectors; protect it like the live index. Secrets (`secrets/`) are not part of this procedure;
back them up separately if you want to preserve issued handles and the credential, otherwise run
`spool init` again after restoring (new signing key = old handles invalid).

Restore: `spool service stop`, replace `state/index.sqlite` with the backup (remove stale
`index.sqlite-wal`/`-shm`), keep mode 0600, `spool service start`, `spool doctor`.

## Upgrades and failures

* Schema migrations apply at daemon start. An incompatible schema or failed migration is a startup
  error; Spool does not delete and rebuild data to hide it.
* At `storage.warning_bytes` status warns; at `storage.pause_ingestion_bytes` ingestion pauses and
  search keeps working. Both thresholds compare the allocated size of `index.sqlite` plus
  `index.sqlite-wal`. Status fields `index_db_free_bytes` and `jobs_db_free_bytes` report reusable
  free-page bytes; those pages still count toward the thresholds.
* SQLite trims the WAL only after a complete checkpoint followed by a subsequent write. It may then
  shrink to 64 MiB, or to the size of the first transaction if that transaction is larger. Open read
  transactions can block checkpointing, and 64 MiB is not a cap.
* To reclaim database free pages manually, take Spool fully offline:
  1. Run `spool service stop`.
  2. Close every client that may have the database open, including `sqlite3`, DBeaver and backup
     clients. Run `lsof "$SPOOL_HOME/state/index.sqlite"*`; it must show no process using the
     database or its WAL/SHM files before continuing.
  3. Run `sqlite3 "$SPOOL_HOME/state/index.sqlite" "VACUUM"`.
  4. Run `spool service start`.

  VACUUM rewrites the database, can require up to twice the current database size in free disk space,
  and can take minutes. Spool never runs VACUUM automatically.
* Changing extraction settings changes the pipeline fingerprint; use `spool index rebuild` to apply.
* Changing `embedding.model`, `embedding.dimensions` or `embedding.profile_generation` creates a new embedding
  profile. The daemon builds it in the background (it is the target of ingestion) while search keeps using the
  previous profile, whose vectors are only ever compared with query vectors of the same model. The switch is one
  transaction that runs when every chunk of the currently published corpus has a vector for the new profile;
  sessions published meanwhile are part of that corpus. `spool status` shows `embedding.profile_id` (target) and
  `embedding.active_profile_id` (queries). The previous profile can answer queries only through the same configured
  endpoint and credential; otherwise semantic search returns a typed error and hybrid falls back to lexical until the
  switch. A changed `embedding` section is read at daemon start, so restart the daemon to start a new migration.
* `embedding.budget_timezone` sets when the daily token budgets reset: `UTC` (default) or a fixed UTC offset such as
  `+05:30`. Named zones with daylight saving are not supported and are rejected at startup. Usage for the current day
  is derived from the persisted requests created inside that day's window, so restarts and zone changes recount it.
* Daemon will not start: `spool doctor`, then `spool logs`; launchd stdout/stderr are in
  `daemon.stdout.log` / `daemon.stderr.log` next to `spool.log`. A lock error means another daemon
  owns the state directory.
* After `spool service stop` on macOS the agent is unloaded; `spool service start` re-bootstraps it.
