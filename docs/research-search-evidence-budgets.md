# Search snippets and expanded evidence: external design comparison

Research date: 2026-11-05. Primary documentation and source only; all external links below were retrieved on that date. This is a design comparison, not an implementation proposal or a benchmark. Moving documentation and unpinned source branches may change.

## Executive synthesis

The useful common pattern is to separate the unit that matches a query from the unit returned for understanding it. Highlighting systems select readable passages after matching a document; parent and sentence-window retrievers expand small matches into larger context; agent tools can separate discovery from fetching. Their documented defaults do **not** establish an optimal Spool excerpt size. The comparison table supplies the supporting sources.

For Spool, first evaluate the existing `search_sessions` → `read_session` workflow. A clipped discovery excerpt is not necessarily clipped final evidence: the reader expands its anchors to complete containing messages plus requested neighbors. The decisive questions are whether the excerpt lets the agent choose the right reference, whether reading it recovers sufficient evidence, and how many calls and tokens that costs. Increasing every excerpt can help one of those stages while harming breadth or cost at another. This is an inference to test, not a measured result.

## Local baseline and strength of evidence

Current contracts separate a configurable 65,536-byte search response, a fixed 1,200 UTF-8-byte match excerpt, at most eight selected source spans, and at most three matches per session. Read responses default to 32,768 bytes and have a 262,144-byte maximum; neighboring conversational-message counts default to two on each side and accept at most twenty. These are different controls. Sources: [search contract](spec.md), [search configuration](../src/config.rs), [evidence selection](../src/search/evidence.rs), [reader types](../src/transcript/types.rs).

Normal recall explicitly takes search followed by read. A match selection resolves excerpt anchors to whole containing messages and neighbors; it stays on a compatible branch. Pagination continues the fixed selection, while navigation opens a different selection. A remote later correction is therefore not guaranteed by merely finishing pagination. Sources: [MCP workflow](mcp-tools.md), [reader contract, sections 3 and 8](read-session-contract.md).

The coordinating investigation supplied these frozen-corpus observations; this research did not rerun them: 50 lexical queries, 484 session rows, 723 matches; 669,039 excerpt-text bytes in aggregate, 925.4 mean bytes per match, 1,087 median, 334 matches at least 1,190 bytes, and all matches marked truncated. Mean excerpt text per query was 13,380.8 bytes, maximum 16,462; these are text-only figures, not serialized response sizes. The harness reported no truncated query response. Thus global budget exhaustion was not the observed failure on that corpus. Three known clipping witnesses already fit within 1,200 bytes when selected appropriately. Earlier full-chunk union also changed grouping and scope budgets and regressed five answer assessments; a selected-window-only grouping lost context-derived relevance. These observations support separating mechanisms in experiments, not attributing the failures to one byte limit. See [local evaluation record](retrieval-eval.md).

The frozen quality assessments are assistant-authored. They diagnose visibility problems; they are neither human ground truth nor an end-to-end measurement of the documented two-call workflow.

This report uses the latter for the default and treats the notebook as an illustration. Neither value is recommended for Spool.

## Distinct budgets and stage boundaries

The table supports a design vocabulary, not a winning design:

1. **Candidate work:** indexed units examined, reranker inputs and source bytes scanned. Increasing this can recover candidates without increasing returned evidence.
2. **Discovery presentation:** which spans become visible, passage count, boundaries and excerpt target. A soft passage target could prefer complete sentences or messages, with explicit fallback when one unit is too large; that is a hypothesis, not current behavior.
3. **Evidence selection:** which messages, exchanges or parent passages a selected match opens. Preserve identity, chronology and provenance when expansion adds text beyond the displayed snippet.
4. **Transport admission:** serialized bytes, envelope overhead, result count and truncation signaling. A hard byte cap remains useful even if passage selection uses softer semantic boundaries.
5. **Model context:** actual tokenizer counts of tool results, repeated history and generated answers. A byte count cannot provide a constant model-token count across prose, code, Unicode and identifiers.

Reranking belongs between broad candidate retrieval and final evidence admission; it need not use the discovery snippet as its only input. Anthropic's [cookbook](https://platform.claude.com/cookbook/capabilities-contextual-embeddings-guide) explicitly describes over-retrieving candidates, scoring them with a reranker, then selecting top-k. That is an extra query-time stage with extra latency and scoring cost; the cookbook's example measurements are not estimates for Spool. First identify whether candidate recall, ordering, excerpt selection or reader expansion is failing.

## Calls, costs and conversation-specific risks

These are Spool-applicable inferences rather than externally measured gains:

- **Larger discovery output** can avoid some exploratory reads or reveal the qualifier needed to select a hit. It also sends extra material for every returned match, including rejected hits, and can displace session breadth once the global cap binds. Measure serialized bytes and model tokens independently.
- **Progressive disclosure** can keep first-call output small and spend context on selected evidence. It adds tool latency, model decision time, reference-selection errors, repeated overlapping text and potentially extra model turns. A local Unix-socket call has a different cost from a remote model inference; counting calls alone is insufficient. Some independent reads can be batched or parallelized by a caller, but do not assume a particular client does so.
- **Repeated context has real cost.** Claude's [search documentation](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool) states search content counts as input both during search iterations and in later conversation turns. Provider caching and client compaction affect actual billing; record the actual caller behavior rather than multiplying raw excerpt bytes by a generic token ratio.
- **Whole sentences are an imperfect transcript unit.** A user request plus assistant response can contain the minimal rationale; a correction may be a later user turn; a tool result may be required to distinguish a proposal from a completed change. Complete messages can also contain huge irrelevant payloads. Test local exchange closure separately from arbitrary full-chunk return.
- **A correction is not just more neighboring text.** A later reversal may lie beyond default neighbors. The agent may need navigation or a targeted follow-up query, then must distinguish proposal, superseded decision and final state. Reading the original clipped message fixes within-message clipping, not every missing later correction.
- **Branch boundaries are correctness boundaries.** Expansion must follow anchored ancestry and compatible continuation. Physical adjacency in JSONL does not justify importing sibling work, a subagent answer or a different branch's outcome. Spool already states this constraint in its [reader contract](read-session-contract.md).
- **Context-derived matching must survive presentation.** Restricting grouping to displayed excerpt windows can remove relevance supplied by indexed context. Conversely, full-chunk union can broaden evidence and duplicate it. Evaluate candidate identity, grouping, anchors and output allocation separately.

## Evidence needed before changing defaults

Use the same frozen queries and ranking inputs to compare current excerpts, better selection within the same byte budget, boundary-aware passages, and larger bounded excerpts. Keep retrieval candidate IDs/ranks and passage bounds fixed where possible, then evaluate candidate construction, expansion and grouping separately. In [evidence selection](../src/search/evidence.rs), `MAX_MATCH_BYTES` also affects window and sample widths and allocation; changing that constant is not a budget-only ablation. Record matches dropped when the global response cap binds. No external system's example size should become a new default without this evidence.

Measure three outcomes separately: discovery lets the caller select the right reference; read exposes sufficient verified evidence; final answer correctly distinguishes historical and current decisions with usable citations. Include the actual two-call workflow, not only an excerpt-sufficiency score. Add a search-only arm to quantify what extra first-call text buys.

Record candidate recall, session diversity, evidence coverage, irrelevant and duplicate bytes, serialized search/read bytes, model-token counts, number of reads, pagination/navigation calls, source-read work, latency distributions and final-answer errors. Report total cost per successful answer, not just search latency or tokens per result. Include cold/warm cache conditions and actual model/provider rates if a later authorized benchmark uses a model.

Stratify cases: complete short facts; rationale needing a question/answer pair; a qualifier inside one long message; negation or a correction later in the same branch; a faraway final decision; multiple relevant sessions; context-only relevance; dense repeated terms; code and Unicode; very large tool results; ambiguous fork continuation; unavailable or changed source; citation/reference stability after truncation. Preserve negative controls where extra context should not change the answer.

Human review should adjudicate the clipping witnesses, corrections and regressions, with a separate held-out set. Assistant-authored labels can help organize cases but must remain labeled as such. Unresolved: whether the current excerpt limit actually reduces end-to-end answer quality, whether better same-budget selection suffices, whether expansion reduces total model cost, and which caller behaviors dominate latency. This research establishes none of those quantities.

No runtime, schema, benchmark, provider call or default changed. Full suites and empirical answer-quality checks were not run for this documentation-only research.
